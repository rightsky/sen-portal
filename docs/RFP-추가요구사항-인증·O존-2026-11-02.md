## SFR-AUTH-01
| 요구사항 번호 | SFR-AUTH-01 |
| --- | --- |
| 요구사항 명칭 | 교육디지털원패스 통합인증 연계 및 전국 교원 · 학생 · 학부모 수용 |
| 요구사항 정의 | 포털과 S존 시스템의 로그인을 교육디지털원패스(교육부 · KERIS 통합인증)와 표준 프로토콜로 연계하고, 자체 회원 DB 없이 인증 토큰의 속성만으로 신원 · 소속 · 역할 후보를 처리하며, 서울시교육청 외 시도교육청 소속 이용자도 같은 흐름으로 수용한다. |
| 요구사항 세부내용 | ① 교육디지털원패스가 제공하는 표준 인증 프로토콜(OIDC 또는 SAML, 연계 규격은 KERIS 제공본 기준)로 연계 모듈을 개발하고, 학생 · 학부모(디지털원패스 연계 포함) · 교원 · 교육청 담당자 4종 이용자 유형을 처리한다. ② 포털(O존)에는 실명 · 연락처 · 보호자 정보 등 회원 식별정보를 저장하지 않으며, 토큰에서 받은 가명 식별자 · 소속 교육청 코드 · 학교 코드 · 학년 · 이용자 유형만 세션에 보관한다. ③ 소속 교육청 코드를 테넌트 식별자로 사용하여 타 시도교육청 소속 이용자를 거부하지 않고 해당 교육청 설정으로 연결하며, 테넌트 미등록 교육청 이용자는 공개 서비스와 역할 없는 교원 범위(집 모드)로 제한한다. ④ 교원 여부 · 재직 상태는 토큰 속성으로 확인하고, 담임 · 담당 학급 등 역할은 SFR-AUTH-02의 승인 절차로만 부여한다. ⑤ 미성년 이용자의 보호자 동의 · 법정대리인 확인은 통합인증 측 절차 결과를 받아 처리하고 포털에서 별도 수집하지 않는다. ⑥ 연계 신청에 필요한 기술 자료(연계 규격 적합성, 토큰 속성 매핑표, 이용 대상 범위 「전국」 설정 근거)를 작성하여 발주기관의 연계 신청을 지원한다. ⑦ 통합인증 장애 시 공개 서비스는 계속 제공되고 로그인 서비스는 안내 화면으로 전환되는 장애 대응을 구현한다. |
| 산출정보 | 통합인증 연계 설계서, 토큰 속성 매핑표, 세션 보관 항목 명세(포털 미저장 항목 명시), 연계 신청 기술 자료, 장애 대응 시험 결과서 |

## SFR-AUTH-02
| 요구사항 번호 | SFR-AUTH-02 |
| --- | --- |
| 요구사항 명칭 | 역할 부여 · 승인 워크플로우(교육청 → 학교 → 학급) |
| 요구사항 정의 | 인증으로 확인된 교원 · 담당자에게 담임 · 과목 교사 · 진학부장 · 학교관리자 · 위촉 상담 선생님 · 교육청 담당자 역할을 승인 절차로 부여하고, 학년도 전환 · 담임 교체 · 위촉 만료 시 자동 회수하는 체계를 구현한다. |
| 요구사항 세부내용 | ① 역할 신청(교원 자기 선언) → 학교관리자 승인(나이스 편성표 대조 결과 표시) → 담당 범위(학년도 · 학교 · 학급 · 임기) 부여의 흐름을 구현하고, 편성표와 불일치하면 반려 또는 범위 수정으로만 처리한다. ② 학교관리자 · 교육청 담당자 역할은 상위 관리자 승인으로만 부여하며, 테넌트(교육청)별로 승인 주체를 분리한다. ③ 위촉 상담 선생님은 교육청 담당자가 지정하고, 첫 로그인 때 전문 계열 · 연락처 · 소속 확인 창을 거치며, 같은 학교 소속 학생 배정은 자동 제외한다. ④ 학년도 전환(3.1), 담임 교체, 위촉 기간 만료, 전보 · 퇴직(토큰 속성 변경)을 감지하여 역할과 담당 범위를 자동 회수하고 일괄 재승인 절차를 제공한다. ⑤ 역할 부여 · 변경 · 회수 이력을 감사 로그에 남기고, 승인 대기 · 만료 예정 건을 관리 화면에 표시한다. ⑥ 담당 범위는 SFR-NEIS-05의 접근 통제 속성으로 그대로 사용된다. |
| 산출정보 | 역할 · 권한 정의서(역할 × 기능 × 범위 매트릭스), 승인 워크플로우 설계서, 자동 회수 규칙서, 감사 로그 항목 명세 |

## SFR-AUTH-03
| 요구사항 번호 | SFR-AUTH-03 |
| --- | --- |
| 요구사항 명칭 | 2단계 인증과 S존 진입 경로 통제 |
| 요구사항 정의 | 학생 단위 식별 정보 화면과 승인 · 배정 · 보관 위치 변경 등 권한 행사 기능에 들어갈 때 2단계 인증을 요구하고, S존 화면 진입 시 접속 경로(업무망 단말 · 외부 단말 보안 경로)를 확인하는 통제를 구현한다. |
| 요구사항 세부내용 | ① 2단계 인증 수단은 간편인증(네이버 · 카카오 · PASS 등 공인 간편인증)과 휴대폰 인증번호를 지원하고, 전자서명이 법적으로 필요한 기능(수능 성적 전송 · 정산 승인)에만 GPKI를 적용한다. ② 2단계 인증 시점은 식별 정보 화면 진입 때로 하고 통과 후 유지 시간(기본 10분)을 설정값으로 둔다(하루 1회 · 로그인마다 방식도 설정으로 전환 가능해야 함). ③ S존 화면 · 전문시스템 · 업무시스템 진입 시 접속 단말이 업무망 단말인지, 외부 단말이면 VPN/ZTNA · 단말 보안 검증 · RBI/VDI 경로를 거쳤는지를 접속 정보(출발지 구간 · 단말 검증 결과 · RBI 세션 식별자)로 확인하고, 확인되지 않으면 진입을 거부하고 안내한다. ④ 세션은 업무시스템 30분, 만료 5분 전 연장 안내, 무입력 20분 화면 잠금(학생상담모드)을 설정값으로 구현한다. ⑤ 2단계 인증 · 진입 거부 · 세션 만료 이력을 감사 로그에 기록한다. |
| 산출정보 | 인증 수단 · 시점 설계서, 접속 경로 확인 규칙서, 세션 정책 설정 명세, 시험 결과서(경로별 진입 허용 · 거부) |

## SFR-PTL-01
| 요구사항 번호 | SFR-PTL-01 |
| --- | --- |
| 요구사항 명칭 | O존 본인 1건 서비스의 비저장 · 입력 통제 |
| 요구사항 정의 | 학생 · 학부모가 포털(O존)에서 쓰는 본인 1건 서비스(나의 포트폴리오 · 자녀 열람 · 상담 신청 · 챗봇)가 포털 구간에 개인 식별 자료를 저장 · 캐시하지 않고, 자유 입력에 성적 · 실명 · 연락처가 남지 않도록 통제한다. |
| 요구사항 세부내용 | ① 포털에서 보여 주는 본인 자료(성적 · 검사 결과 · 상담 기록 · 포트폴리오)는 CDS를 거쳐 S존에서 1건 단위로 받아 응답 후 폐기하고, 포털 DB · 캐시 · 로그에 저장하지 않는다. ② 학생이 포털에서 입력 · 저장하는 자기 신고 성적 · 활동 기록 · 관심 목록 · 지원계획은 CDS를 거쳐 S존 저장소에 저장하고, 포털에는 세션 범위의 임시 상태만 둔다. ③ 학부모 자녀 열람은 법정대리인 확인 결과와 자녀의 항목별 동의(opt-in)가 모두 있는 항목만 1건 응답하고, 열람마다 자녀 알림(하루 묶음)과 열람 이력을 남긴다. ④ 게시판 질문 · 챗봇 질문 · 메모 등 자유 입력은 주제 선택 등 구조화 입력을 기본으로 하고, 저장 · 전송 전에 성적 숫자 · 실명 · 연락처 · 이메일 · 학교명 등 민감 표현을 탐지하여 경고 후 저장을 막으며, 탐지 규칙은 운영자가 수정할 수 있어야 한다. ⑤ 챗봇 답변은 근거 출처와 기준일을 표시하고 합격 가능성 · 확률을 제시하지 않으며, 학생 · 학부모에게는 근거 자료 범위 안의 답과 「자료에 없음」 안내까지만 제공한다. ⑥ 포털 구간 미저장을 증명하는 저장 자료 목록 · 로그 마스킹 규칙 · 캐시 정책을 설계서에 명시한다. |
| 산출정보 | 본인 1건 응답 흐름 설계서, 포털 구간 저장 자료 목록(미저장 항목 명시), 입력 통제 규칙서, 열람 동의 · 알림 명세, 챗봇 답변 규칙서 |

## 발주기관 협조 사항(업체 과업 아님, RFP 「발주기관 지원 사항」에 기재)
- 교육디지털원패스 연계 서비스 등록 신청(이용 대상 범위 「전국」)과 KERIS 승인
- 타 시도교육청과의 공동활용 협약, 개인정보 처리 위탁 · 공동 이용 관계 확정, 저작권 · 라이선스 조항
- 학생 · 보호자 동의 수집(학교 → 교육청 제공), 학교 참여 승인 운영
- 보안성 검토 · 개인정보 영향평가 · 교육청 정보보안 심의 신청(업체는 기술 자료 작성 지원)
- 업무망 단말 · RBI/VDI · VPN/ZTNA 인프라와 단말 개인정보 검출 솔루션 운영
