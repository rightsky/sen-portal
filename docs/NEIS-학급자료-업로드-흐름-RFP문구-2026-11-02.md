# NEIS 학급 자료 업로드(Plan A) 최종 흐름과 RFP 요구사항 문구 (2026-11-02)

용도 : '27 RFP 요구사항에 포함할 원문. 2026-11-02 사용자와 논의해 확정한 내용이며, 「NEIS 연계 Plan A(현행 방식)」의 보안 통제를 구체화한 것이다. Plan B(NEIS 배치 연계)로 전환하면 ①②③⑥이 없어지고 ④⑤만 남는다. 관련 문서 : claude/NEIS-연계-PlanA-PlanB.md, claude/보안검토-목업적용방안-2026-11-02.md, claude/학습데이터-보안구조-결정.md.

## 1. 논의에서 정리된 판단
- 서버가 교육청에 있어도 NEIS(처리자 학교장) → SEN(처리자 교육감)은 법적으로 「제공」이므로 학생 · 보호자 동의(초 · 중등교육법 30조의6)가 1차 근거. 교육감 소관 업무 근거(경로 D)는 법률 검토 뒤에만.
- 건별 학교장 전자결재는 두지 않는다. 학기 초 학교 단위 1회 참여 승인(담당자 · 학급 · 데이터군 · 시점)이 반출 승인을 대신하고, 건별은 게이트 이력으로 기록한다. 승인 범위 밖만 그때 승인.
- 서버 구간 : 파일을 디스크에 두지 않고 메모리에서 처리(방안 1). 「완벽히」가 아니라 미들웨어 · 앞단 장비 · 파서 · 로그/덤프/스왑 · 트랜잭션 다섯 구간의 설정을 맞췄을 때 성립.
- PC 구간 : 자동 삭제 에이전트 대신 안내 팝업 + 감사 로그(방안 2)를 채택하되, 단독으로는 「안내했다」의 증거일 뿐이므로 NEIS 다운로드 암호화 · 단말 개인정보 검출 솔루션 점검 · (Edge · Chrome) File System Access API 원본 삭제를 붙인다.
- 게이트는 업무망 하나뿐. 포털(O존) · 메일 · 공유 폴더 · 집 PC로는 갈 길이 없다.

## 2. 최종 흐름
⓪ 학교 참여 승인(연 1회, 학기 초) : 학교장이 SEN 참여 · 담당자(학교관리자 역할 1~2명) · 대상 학급 · 데이터군 · 적재 시점(연 3회 : 학기말 7 · 1월, 수시 전 8월)을 결정하고 S존 「학교 관리 › 학교 참여」에 등록 → 학생 · 보호자 동의 명단 등록. 이 등록값이 게이트의 허용 범위가 되며 건별 반출 결재를 대신함
→ ① 담당자가 학교 업무 PC(업무망)에서 NEIS 로그인
→ ② 담당 학급 자료를 내려받음 : NEIS 다운로드 암호화 적용 파일, 동기화되지 않는 전용 폴더
→ ③ 업무망 파일 게이트에 업로드(통합인증 + MFA) : 이력 기록(담당자 · 학교 · 학급 · 시각 · 파일 해시 · 행 수)
→ ④ 서버 메모리 처리 : 디스크 저장 없이 복호화 → 악성코드 검사 → 표준 템플릿 형식 검사 → 범위 검사(⓪ 허용 범위 밖은 거부) → 동의 명단 대조(미동의 행 제외) → 트랜잭션 적재 → 메모리 해제. 결과(적재 · 제외 · 거부)를 담당자 화면에 즉시 표시
→ ⑤ S존 적재 : 담당 학급 한정(ABAC + RLS), 데이터 · 키 테이블 분리, 비식별 기본에 담임 반만 예외, 학년도 · 학기 스냅샷, 적재 이력 · 미적재 학급 관리
→ ⑥ PC 원본 파기 : 적재 성공 즉시 「NEIS 파일을 지금 파기하세요」 확인 팝업(확인 전 화면 진행 불가) → 확인 클릭을 감사 로그에 기록 → Edge · Chrome이면 업로드에 쓴 원본 파일을 File System Access API로 즉시 삭제(사용자 권한 확인 1회) → 교육청 단말 개인정보 검출 솔루션의 주기 점검 결과를 파기 증빙으로 연결

규칙 : 게이트는 업무망 하나뿐 · ⓪ 범위 안은 기록만, 밖은 그때만 승인 · Plan B 전환 시 ①②③⑥이 없어지고 ④⑤만 남음.

남는 위험 : 사람 실수(다른 학급 파일 → ④ 범위 검사가 막음), NEIS 다운로드 권한 자체(NEIS 쪽 권한 관리), 삭제 이전에 사본이 생긴 경우(동기화 폴더 · 자동 복구 파일 → 전용 폴더 + 단말 점검으로 대응).

## 3. RFP 요구사항 문구

| 요구사항 번호 | SFR-NEIS-01 |
| --- | --- |
| 요구사항 명칭 | NEIS 학급 자료 업로드의 서버 메모리 처리 및 파일 미저장 |
| 요구사항 정의 | 학교 담당자가 업무망 파일 게이트로 올린 NEIS 학급 자료(암호화 파일)를 서버 디스크에 파일 형태로 저장하지 않고 메모리에서 복호화 · 검사 · 파싱 · 적재한 뒤 즉시 해제하여, 서버 구간에 S등급 파일이 남지 않도록 한다. |
| 요구사항 세부내용 | ① 업로드 요청 본문은 웹 서버 · WAS · 파서 전 구간에서 디스크 임시 파일을 생성하지 않도록 구성하고(멀티파트 메모리 처리, 앞단 프록시 · WAF 본문 버퍼링 금지 또는 암호화 임시 영역 즉시 삭제, 파서 스트리밍 모드), 파일 크기 상한(기본 20MB)을 둔다. ② 메모리 내에서 복호화 → 악성코드 검사 → 표준 템플릿 형식 검사 → 학교 참여 등록 범위 검사 → 동의 명단 대조를 순서대로 수행하고, 하나라도 실패하면 적재하지 않고 사유를 화면에 표시한다. ③ 적재는 트랜잭션으로 처리하여 전부 성공 또는 전부 취소만 허용한다. ④ 요청 로그 · 오류 로그 · APM에 자료 행이 기록되지 않도록 마스킹하고, 힙 덤프 · 코어 덤프 생성을 금지하며 스왑 영역은 암호화한다. ⑤ 업로드 이력에는 파일 대신 담당자 · 학교 · 학급 · 시각 · 파일 해시 · 행 수 · 검사 결과 · 적재 결과를 기록한다. ⑥ 수행사는 위 ①~④의 설정값을 점검표로 작성하여 보안성 검토 증빙으로 제출한다. |
| 산출정보 | 업로드 처리 설계서, 구간별 파일 미저장 설정 점검표, 업로드 이력 명세, 검사 규칙 명세, 시험 결과서(디스크 임시 파일 미생성 확인 포함) |

| 요구사항 번호 | SFR-NEIS-02 |
| --- | --- |
| 요구사항 명칭 | 업로드 완료 후 PC 원본 파일 파기 안내 및 감사 로그 |
| 요구사항 정의 | NEIS 학급 자료 업로드가 성공하면 담당자에게 업무 PC의 원본 파일 파기를 즉시 안내하고 확인 이력을 감사 로그로 남기며, 지원 브라우저에서는 업로드에 사용한 원본 파일을 삭제한다. |
| 요구사항 세부내용 | ① 적재 성공 응답과 동시에 파기 안내 창을 표시하고, 담당자가 「파기했습니다」를 확인하기 전에는 다음 화면으로 진행할 수 없게 한다. 안내 문구에는 파일 위치(다운로드 폴더 · 바탕화면 등), 암호 파일 포함, 사본 · 휴지통 비우기를 명시한다. ② 확인 클릭 시각 · 담당자 · 학교 · 학급 · 업로드 이력 번호를 감사 로그에 기록하고, 감사 로그는 위 · 변조 방지 저장소에 보관한다. ③ File System Access API를 지원하는 브라우저(Edge · Chrome)에서는 업로드 파일 선택을 해당 API로 받고, 적재 성공 뒤 사용자 권한 확인을 거쳐 선택한 원본 파일을 삭제하며 삭제 결과를 감사 로그에 기록한다. 미지원 브라우저에서는 ①②만 수행하고 그 사실을 기록한다. ④ 관리자 화면에서 학교 · 기간별 파기 확인 이력과 미확인 건을 조회 · 내보내기할 수 있어야 한다. ⑤ 교육청 단말 개인정보 검출 솔루션의 점검 대상에 NEIS 학급 자료 파일 패턴을 등록할 수 있도록 파일명 · 서식 규칙을 제공하고, 점검 결과와 감사 로그를 대조할 수 있는 식별자(업로드 이력 번호)를 둔다. |
| 산출정보 | 파기 안내 화면 설계서, 감사 로그 항목 명세, 브라우저별 원본 삭제 동작 명세, 파기 확인 이력 조회 화면 설계서, 단말 점검 연계 규칙서 |
